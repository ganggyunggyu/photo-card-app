# 키오스크 카드배출기 보드 + ESP32(BLE) 연동 배선/검증 가이드 (갤탭+크롬)

이 문서는 “유효 쿠폰 → ESP32로 BLE `PRINT` → 카드배출기 보드 TRIG 입력 펄스” 구조를 기준으로, **4핀 외부 커넥터 타입 카드배출기 보드**를 가장 안전하게 결선하는 방법과 **현장에서 핀아웃을 확정(검증)하는 절차**를 정리한다.

시스템 전체 흐름(하드웨어/소프트웨어 포함): `docs/SYSTEM_OVERVIEW.md`

> 중요: 실제 핀 기능은 제조사/모델마다 다르다. 이 문서는 “현장 빈출 패턴”을 기반으로 한 가설을 **측정으로 확정**하는 방식이다. 측정 없이 ESP32 GPIO에 직결하지 않는다.

## 0) 안전 주의(필독)

- 카드배출기 보드가 AC(220V) 장비 내부에 포함돼 있을 수 있다. **고전압 구간은 작업하지 않는다.**
- ESP32 GPIO는 **3.6V 초과 입력 금지**다. OUT/SEN이 5V/12V/24V면 레벨 변환 없이 직결하면 고장난다.
- 전원은 반드시 “보드 전원(+12V/+24V)”과 “ESP32 전원(5V/3.3V)”을 분리해서 설계한다(DC-DC 사용).

## 1) 한 줄 결론(버튼 대체의 본질)

- 물리 버튼은 결국 **“두 선을 잠깐 쇼트(접점 닫힘)”** 시키는 행위다.
- 그래서 키오스크에서 “웹 바코드 트리거로 버튼 대체”의 핵심은, **ESP32가 그 ‘잠깐 쇼트’를 대신 만들어주는 회로**를 붙이는 거다.

## 2) 웹 바코드 트리거의 하드웨어적 성격(현장 기준)

현장 키오스크에서 흔한 USB 바코드 리더는 보통 **Keyboard Wedge(키보드 웨지)** 방식이다.

- 스캐너는 숫자를 키보드처럼 빠르게 입력하고, 마지막에 `Enter`/`Tab` 같은 suffix로 “스캔 확정”을 만든다.
- 웹에서는 “키 입력 스트림 → `Enter` 도착 시 1회 트리거”로 처리하는 게 일반적이다.
- 사람 타이핑과 구분할 때는 “키 입력 간격이 매우 짧다”를 이용해서 버퍼링/타임아웃으로 필터링한다.

## 3) 버튼 대체 회로 3대장(현장 표준)

TRIG 입력 스펙이 불확실할수록, “ESP32가 직접 전압을 밀어넣는 구조”는 피하고 **당기기(오픈컬렉터)** 또는 **절연(옵토)**으로 간다.

### 3-1) 트랜지스터 오픈컬렉터(Active-Low: GND로 당김)

원리: ESP32 GPIO로 NPN을 켜서 `TRIG/IN`을 순간적으로 `GND`에 연결한다.

- 장점: 부품 최소, 싸고 안정적, TRIG 쪽 전압이 5V/12V여도 “직결 사고”를 피하기 쉽다
- 단점: 절연이 없어서 접지/노이즈 환경이 나쁘면 영향 받을 수 있다

### 3-2) 옵토커플러(포토커플러)로 절연된 버튼 만들기(권장)

원리: ESP32(3.3V)와 카드배출기 보드(12V/24V/노이즈)를 **광학적으로 분리**하고, 보드 쪽은 오픈컬렉터처럼 TRIG를 당겨준다.

- 장점: 접지 루프/전위차/모터 노이즈에 강해서 현장 안정성이 좋다
- 단점: 부품이 조금 늘어난다(그래도 이게 정상 설계에 가깝다)

### 3-3) 릴레이(리드 릴레이/SSR 포함)로 건식 접점 복제

원리: 릴레이 접점으로 “두 선을 붙였다 떼는” 동작 자체를 그대로 만든다.

- 장점: 보드가 “건식 접점(dry contact)”만 받는 타입이면 제일 깔끔하다
- 단점: 부피/소모/코일 노이즈(필요하면 보호 소자 고려)

## 4) 4핀 커넥터 가설(현장 표준)과 검증 포인트

“모터 2핀 + 센서 3핀 + 전원”이 4핀에 동시에 들어가는 건 물리적으로 불가능하므로, 외부 4핀은 보통 아래처럼 떨어진다.

현장에서 자주 보는 구성:
- 보드에 `2핀(모터)`, `3핀(센서)`, `4핀(외부 인터페이스)` 커넥터가 **각각 따로 존재**한다.
- 이 경우 모터/센서는 이미 보드에 붙어 있으니, 우리가 제어해야 하는 건 보통 **4핀의 전원(+V/GND) + TRIG(+ 선택적으로 OUT/SEN)** 쪽이다.

### 4-1) 패턴 A(가장 흔함): 전원 2 + 트리거 1 + 상태 1

| Pin | 이름(가정) | 설명 |
|---:|---|---|
| 1 | `+V_MOTOR` | 보드 전원(+12V 또는 +24V) |
| 2 | `GND` | 기준 접지 |
| 3 | `TRIG/IN` | 배출 시작 입력 |
| 4 | `OUT/SEN` | 배출 완료/카드 감지 출력 |

자주 나오는 특성:
- `TRIG/IN`: **Active-Low(= GND로 당기면 동작)** 또는 “드라이컨택트” 입력인 경우가 많다.
- `OUT/SEN`: 오픈컬렉터(풀업 필요) 또는 TTL(5V/12V) 출력일 수 있다.

### 4-2) “이 가설이 맞는지” 확정하는 현장 검증 절차(권장 10분)

준비물:
- 멀티미터(전압/도통)
- 저항 1k~2.2k 1개(트리거 테스트용, 안전한 쇼트용)
- 가능하면 전원에 퓨즈/전류 제한(실수 방지)

절차:
1. **라벨/실크 확인**
   - 커넥터 근처에 `12V`, `GND`, `IN`, `OUT` 같은 표기가 있으면 그게 정답이다.
2. **GND 찾기(도통)**
   - 보드의 전원 음(-)단/대형 GND 폴리곤과 도통되는 핀이 `GND`일 확률이 높다.
3. **+V 찾기(전압)**
   - 보드에 전원을 넣고, `GND` 기준으로 나머지 핀 전압을 잰다.
   - +12V/+24V가 뜨는 핀이 `+V_MOTOR`다.
4. **TRIG/IN 성격 확인(Active-Low 여부)**
   - `TRIG` 후보 핀의 유휴 전압을 잰다.
     - 유휴 시 +V 또는 5V 근처로 떠 있으면(풀업) Active-Low일 가능성이 크다.
   - **1k~2.2k 저항을 통해** `TRIG`를 `GND`에 100~300ms 정도만 연결해본다.
     - 이때 배출이 시작되면: `TRIG`는 “GND로 당기는 입력”이 맞다.
5. **OUT/SEN 전압 레벨 확인**
   - 유휴/동작 시 `OUT` 전압을 잰다.
     - 만약 **3.3V를 초과**한다면 ESP32에 직결 금지(레벨 변환 필요).
     - 유휴 때 전압이 뜨지 않고(부유) 동작 때만 내려가는 듯하면 오픈컬렉터일 수 있다.

## 5) 전원 구성(권장, 12V 10A DC 어댑터/SMPS 기준)

### 5-1) 전원 배선

- 12V 10A DC 어댑터(+) → 카드배출기 보드 `+V_MOTOR`
- 12V 10A DC 어댑터(-) → 카드배출기 보드 `GND`

ESP32 전원은 아래 둘 중 하나로 간다(둘 다 가능).

- 옵션 A(권장): 12V 10A DC 어댑터 출력 → DC-DC Buck(12V→5V) → ESP32 `5V/VIN`
- 옵션 B: ESP32는 **별도 USB 5V**(충전기/보조배터리)로 공급
  - 이 경우에도 **GND는 반드시 공통**으로 묶어야 한다(아래 5-2 참고).

### 5-2) GND(공통 접지)

신호가 성립하려면 기준점이 같아야 하므로:

- 카드배출기 보드 `GND` ↔ ESP32 `GND`는 **반드시 공통 접지**

예시(옵션 B, ESP32를 USB로 따로 먹일 때):

```
12V 어댑터 (-) ─────────────┬─ 카드배출기 보드 GND(4핀 흑)
                            └─ ESP32 GND
```

## 6) TRIG/IN 결선(가장 안전한 기본안: “오픈컬렉터로 GND 당기기”)

`TRIG/IN`이 Active-Low(또는 드라이컨택트)일 때, ESP32가 “밀어넣는” 대신 “당기는” 역할만 하게 만들면 전압 사고가 크게 줄어든다.

중요:
- `4핀 TRIG`를 ESP32 GPIO에 **직결(그냥 선으로 연결)** 하는 건, TRIG 레벨이 3.3V 이하로 보장되지 않으면 금지다.
- TRIG가 5V/12V/24V 풀업이면 ESP32 입력이 바로 터질 수 있으니, 아래처럼 NPN/옵토/릴레이 중 하나로 “버튼”을 복제한다.

### 6-1) NPN 트랜지스터(권장) 결선

부품:
- NPN(2N2222/SS8050 등) 1개
- 베이스 저항 2.2k 1개
- (권장) 베이스 풀다운 100k 1개

배선:

| ESP32 | 부품 | 카드배출기 보드 |
|---|---|---|
| `GPIO 4` | `2.2k` → NPN `B` | - |
| `GND` | NPN `E` | `GND`(공통) |
| - | NPN `C` | `TRIG/IN` |

옵션(권장):
- NPN `B` ↔ `GND`에 100k(풀다운)로 부팅 시 오동작(플로팅) 확률을 낮춘다.

동작:
- `GPIO 4 = HIGH` → NPN ON → `TRIG`를 `GND`로 당김 → 배출 시작
- `GPIO 4 = LOW` → NPN OFF → 배출 정지(입력 유휴)

### 6-2) TRIG가 Active-High인 경우(예외)

측정 결과 `TRIG`가 “+V 펄스 입력”이면(Active-High), 위 NPN 풀다운 방식은 맞지 않는다.

이 경우 권장:
- 제조사 매뉴얼의 입력 스펙(+V, 허용 전류)을 확인 후
- **릴레이 접점** 또는 **옵토커플러**로 “규정된 전압 펄스”를 만드는 방식으로 전환한다(직결 금지).

### 6-3) 5V 1채널 릴레이 모듈(LOW 트리거)로 “진짜 접점” 복제

카드배출기 보드 `TRIG`가 “버튼처럼 두 선을 붙이면 동작”하는 타입이면, 릴레이가 가장 직관적이다.

정리:
- `COM/NO/NC`는 **전원을 공급하는 단자**가 아니라, “두 선을 붙였다 떼는 스위치(건식 접점)”다.
- 대신 릴레이 **모듈 자체**는 코일/구동회로가 돌아야 하므로 **`VCC(5V)`와 `GND` 전원을 반드시 공급**해야 한다.

중요:
- 흔한 5V 릴레이 모듈은 **입력이 LOW(0V)일 때 릴레이가 붙는(Active-Low)** 타입이 많다.
- 이 경우 ESP32 펌웨어에서 릴레이 ON/OFF를 반대로 잡아야 한다(기본은 OFF = HIGH, 트리거 시 LOW).

#### 제어부(ESP32 ↔ 릴레이 모듈)

| 릴레이 모듈 | ESP32 |
|---|---|
| `VCC(5V)` | `5V/VIN`(또는 DC-DC 5V 출력) |
| `GND` | `GND` |
| `IN` | `GPIO`(예: `GPIO4`) |

주의:
- 모듈이 5V 로직만 “엄격하게” 요구하면 ESP32 3.3V로 `IN` HIGH가 애매할 수 있다. 이때는 `IN`을 **NPN으로 당겨서**(오픈컬렉터) 구동하거나, `JD-VCC` 분리형 모듈을 쓰는 쪽이 안전하다.

#### 접점부(릴레이 COM/NO ↔ 카드배출기 보드 TRIG/GND)

Active-Low(= TRIG를 GND로 당기면 동작) 가정 시:

- `COM` → 보드 `TRIG/IN`(4핀 청록/흰)
- `NO` → 보드 `GND`(4핀 흑)
- `NC`는 미사용

이렇게 하면 릴레이가 붙는 순간에만 `TRIG`와 `GND`가 쇼트돼서 “버튼 누름”이 복제된다.

## 7) OUT/SEN 결선(ESP32 보호가 우선)

OUT은 타입이 갈릴 수 있으니, **측정으로 타입 확정 후** 아래 중 하나로 결선한다.

### 7-1) 케이스 A: OUT이 오픈컬렉터/스위치(= GND로만 내려가는 출력)

배선:
- ESP32 GPIO(입력) ↔ OUT 직접 연결
- ESP32 측에서 3.3V 풀업 제공(외부 10k 권장, 또는 내부 풀업 사용)

```
ESP32 3.3V ──[10k]──+── ESP32 GPIO(입력)
                    |
                   OUT(보드)
보드 GND ───────────+── ESP32 GND(공통)
```

### 7-2) 케이스 B: OUT이 5V/12V/24V “전압 출력”(TTL)

OUT을 멀티미터로 재서, HIGH가 3.3V 초과라면 전압을 낮춘다.

가이드(예시):
- OUT이 5V면: 분배 또는 레벨시프터 사용
- OUT이 12V면: 분배(R1/R2)로 3.3V 이하로
- OUT이 24V면: 분배 비율을 24V 기준으로 설계

예시(12V HIGH 가정):

```
OUT ──[47k]──+── ESP32 GPIO(입력)
             |
            [15k]
             |
            GND
```

중요:
- 분배 저항값은 “보드 HIGH 전압”을 확정한 뒤에 잡는다.
- 불확실하면 옵토커플러/절연 입력으로 설계를 올리는 게 안전하다.

## 8) ESP32 펌웨어 기준 핀/펄스(현재 레포)

`esp32/photo_card_trigger.ino` 기준:

- 출력 핀: `GPIO 4` (현재 `RELAY_PIN`)
- 트리거 시간: `TRIGGER_DURATION_MS = 500`

NPN 풀다운 결선이면 “GPIO HIGH → TRIG를 GND로 당김”이 되므로, 펌웨어 수정 없이도 동작시킬 수 있다(핀만 그대로 쓰면 된다).

## 9) 결선 요약(작업용)

1) 전원
- 12V 10A DC 어댑터 → 카드배출기 보드 `+V/GND`
- 12V 10A DC 어댑터 → DC-DC(12→5) → ESP32 5V

2) 접지
- 보드 `GND` ↔ ESP32 `GND` 공통

3) 트리거(Active-Low 가정, 권장)
- ESP32 `GPIO4` → 2.2k → NPN `B`
- NPN `E` → GND
- NPN `C` → 보드 `TRIG/IN`

대안(릴레이 모듈로 접점 복제):
- 릴레이 `COM` → 보드 `TRIG/IN`
- 릴레이 `NO` → 보드 `GND`

4) 센서
- OUT 전압을 멀티미터로 먼저 확인
- 3.3V 이하(오픈컬렉터 포함)면 풀업/직결
- 3.3V 초과면 레벨 변환(분배/절연)

## 10) 최종 검증 체크리스트

- [ ] `+V_MOTOR` 전압(+12V/+24V) 측정 완료
- [ ] `GND` 확정 및 공통 접지 완료
- [ ] `TRIG`가 Active-Low인지 저항 통해 테스트 완료
- [ ] `OUT` HIGH 전압이 3.3V 이하인지 확인(초과 시 레벨 변환 적용)
- [ ] 웹에서 유효 쿠폰 처리 성공 시 ESP32 `PRINT` 수신 → TRIG 펄스 출력 확인

## 11) 최종 결선(현재 기준: 4핀 전원 + 릴레이로 TRIG 쇼트)

전제(현장 기준, 반드시 멀티미터로 확정):
- `4핀 적 = +12V`, `4핀 흑 = GND`
- `4핀 청록/흰 = TRIG/IN` (Active-Low: GND로 당기면 동작)

### 11-1) 전원

- 12V 10A DC 어댑터 `+` → `4핀 적(+V)`
- 12V 10A DC 어댑터 `-` → `4핀 흑(GND)`
- 12V → DC-DC Buck(12→5) → `5V` 라인 생성
  - `5V` → ESP32 `VIN/5V` 핀
  - `5V` → 릴레이 모듈 `VCC(5V)`
  - `GND`는 모두 공통(어댑터 `-` / 보드 `GND` / ESP32 `GND` / 릴레이 `GND`)

### 11-2) 릴레이 접점(버튼 복제)

접점은 “전원 공급”이 아니라 “두 선 쇼트”다.

- 릴레이 `COM` → `4핀 TRIG(청록/흰)`
- 릴레이 `NO` → `4핀 GND(흑)`
- 릴레이 `NC`는 미사용

### 11-3) 릴레이 제어 입력(IN1) 연결

릴레이 모듈이 `LOW 입력 시 동작(Active-Low)` 타입일 때, `IN1` 직결은 모델에 따라 위험할 수 있다(입력 풀업이 5V인 경우).

권장(안전):
- **NPN으로 `IN1`을 GND로 당기는 방식**
  - ESP32 `GPIO4` → `2.2k` → NPN `B`
  - NPN `E` → `GND`
  - NPN `C` → 릴레이 `IN1`
  - (옵션) NPN `B` ↔ `GND`에 `100k` 풀다운
  - 이 구조면 ESP32는 5V를 직접 맞지 않고, `GPIO4=HIGH`에서 릴레이가 붙도록 만들 수 있다(펌웨어 변경 부담이 줄어듦).

직결(간단, 비추):
- ESP32 `GPIO4` → 릴레이 `IN1` 직결은
  - `IN1-GND`를 멀티미터로 찍었을 때 **유휴 전압이 3.3V 이하**로 확인되고
  - 릴레이가 3.3V 로직을 안정적으로 인식하는 경우에만 시도한다.

### 11-4) 결선 순서(실수 방지)

1) 4핀 하네스가 기존에 어디서 전원을 받는지 먼저 확인(중복 전원/역전원 방지)
2) 12V 어댑터로 보드 전원만 먼저 인가(+V/GND 확인)
3) DC-DC로 5V 만든 뒤 ESP32/릴레이 모듈 전원 인가
4) 릴레이 접점(COM/NO)을 TRIG/GND에 연결
5) BLE 연결 후 테스트(유효 쿠폰 → `PRINT` → 릴레이 “딸깍” + 배출 확인)
